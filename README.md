# future-core — Durable Task Core (этап A)

Надёжное ядро задач для будущей системы из нескольких ИИ. Хранит задачи в одном файле
SQLite, ведёт журнал, делает контрольные точки, повторяет временные ошибки с ограничением
и безопасно восстанавливается после сбоя. ИИ-модели пока **не подключены** — это этап D.

- Язык: Python 3.10 или новее. Ядру не нужны внешние библиотеки.
- Тесты: pytest (`requirements-dev.txt`).
- Подробная спецификация: [SPEC.md](SPEC.md). Список тестов: [docs/TESTS.md](docs/TESTS.md).
- Состояние проекта: [PROJECT_STATE.md](PROJECT_STATE.md). Пакет для следующего ИИ: [HANDOFF.md](HANDOFF.md).

## Структура

```
future-core/

├── docs/TESTS.md           что проверяет каждый тест
├── taskcore/
│   ├── __init__.py
│   ├── __main__.py         командная строка: python -m taskcore ...
│   ├── core.py             ядро: состояния, очередь, попытки, checkpoints, восстановление
│   ├── db.py               подключение к SQLite, транзакции, миграции
│   ├── migrations.py       схема базы (версия 1)

```

## Команды (на любом компьютере или облачной консоли)

```bash
python3 -m pip install -r requirements-dev.txt   # один раз
python3 -m pytest -v                             # все тесты
python3 -m taskcore demo                         # демонстрация, в конце "DEMO OK"
```

Работа с собственной базой (по умолчанию `data/taskcore.db`):

```bash
python3 -m taskcore init
python3 -m taskcore add "Моя первая задача"
python3 -m taskcore list
python3 -m taskcore show 1
python3 -m taskcore recover        # запускать после каждого перезапуска
python3 -m taskcore handoff 1      # пакет передачи задачи другому ИИ
```

## Как проверить с iPhone (Safari)

### Вариант 1 (рекомендуемый): GitHub + GitHub Actions — бесплатно

Тесты запускаются на серверах GitHub, а результат виден в Safari как зелёная галочка.
По документации GitHub, Actions бесплатны для публичных репозиториев на стандартных
серверах, а для приватных на бесплатном тарифе дают 2000 минут в месяц. Один прогон этих
тестов занимает около минуты на каждую версию Python.

1. Файлы попадают в репозиторий (это может сделать Claude по вашему разрешению — так
   проще всего, потому что Safari на iPhone не умеет загружать папки целиком).
2. В Safari откройте `github.com/<ваш-логин>/<репозиторий>` → вкладка **Actions**.
3. Откройте последний запуск **tests**. Зелёная галочка = все тесты и демо прошли на
   Python 3.10, 3.12 и 3.13. Красный крестик = нажмите на него и пришлите скриншот.
4. Перезапуск вручную: Actions → tests → **Run workflow**.

### Вариант 2: PythonAnywhere (бесплатный аккаунт) — ручная проверка

Подходит, чтобы самому запустить команды в браузерной консоли.

1. Safari → `pythonanywhere.com` → создайте бесплатный аккаунт (Beginner).
2. Вкладка **Files** → **Upload a file** → выберите `future-core.zip` из приложения «Файлы».
3. Вкладка **Consoles** → **Bash**. Введите по очереди:
   ```bash
   unzip -o future-core.zip
   cd future-core
   python3 -m pip install --user -r requirements-dev.txt
   python3 -m pytest -v
   python3 -m taskcore demo
   ```
4. Ожидаемый итог: строка `35 passed` и `DEMO OK`.

Ограничения бесплатного PythonAnywhere (по их странице на октябрь 2026): 100 секунд
процессорного времени, 512 МБ диска, 2 консоли; новым бесплатным аккаунтам (после
января 2026) **не даются задачи по расписанию**, веб-приложение отключается через месяц
без продления.

## Что работает постоянно, а что нет

Бесплатная инфраструктура не даёт гарантированной работы 24/7. В этой системе
непрерывность обеспечивается не вечно работающим процессом, а тем, что всё состояние
лежит в базе, а `recover()` после любого перезапуска возвращает задачи в безопасное
состояние. На этапе A исполнитель запускается вручную или в тестах; запуск по
расписанию появится на следующих этапах (кандидат — расписание GitHub Actions).

## Безопасность

- Никаких ключей API в коде, в базе (таблица `providers` отклоняет похожие на ключи
  данные) и в пакете передачи (вычищаются).
- Файл базы и `.env` исключены из git через `.gitignore`.
